# Education

Лична, изпълнима Java/Spring инженерна knowledge base с примери, тестове и обяснения на български език.

Целта на repository-то не е да събира копирани snippets, а да превръща полезни материали от видеа, документации и реални production проблеми в малки лаборатории, които могат да бъдат стартирани, променяни и доказвани с тестове.

## Основни правила

- Кодът, имената на класове, методи, полета и package-и са на английски.
- README документацията и обяснителните коментари са на български.
- Всеки пример трябва да показва **какъв проблем решава**, **защо възниква**, **как можем да го докажем** и **как изглежда доброто решение**.
- Всеки учебен модул следва задължителен flow: **реален входен казус → разбиране на проблема → bad/good решение → доказателство → изходно обобщение**.
- README не започва директно с API или код. Първо трябва да е ясно **каква реална ситуация имаме, какво може да се обърка, защо проблемът е важен и какво ще научим**.
- README не приключва само с описание на API. В края се връщаме към първоначалния казус и описваме **какво решихме, защо решението е по-добро, ограниченията му, кога да го използваме/не използваме, mental model и practical checklist за реален проект/code review**.
- Когато е полезно, пазим `bad` и `good` вариант за директно сравнение.
- `bad` примерът трябва да е реалистичен и да обяснява защо изглежда разумно, а не да е нарочно очевидно грешен код.
- Примерите в `src/main` са production-like; тестовете и експериментите са в `src/test`.
- README е основната учебна документация. Важните концепции в него трябва да сочат с **директни относителни линкове към конкретните source/config/test файлове**, които ги демонстрират.
- Всеки модул има кратка карта **`README → код`**, за да може от теорията да се стигне до изпълнимия пример с един клик.
- В Java кода коментираме основно **защо** е използван даден подход и нетривиалното поведение; не дублираме целия README като JavaDoc/коментари.
- За persistence/database теми, когато е практично, примерите трябва да разглеждат PostgreSQL и Oracle и да описват специфичните разлики.
- За подходящи теми може да има `exercise` и `solution` варианти.
- Използваме Java 25 като основна LTS версия и актуална съвместима Spring Boot 4.x версия.

## Учебен flow

```text
реален казус
→ защо е проблем
→ какво ще научим
→ naive / bad вариант
→ root cause
→ good решение
→ тест / доказателство
→ връщане към началния казус
→ какво научихме + кога да го използваме + checklist
```

Подробният стандарт за входа, изхода и финалната проверка на всеки модул е в [`docs/LEARNING-MODULE-TEMPLATE.md`](docs/LEARNING-MODULE-TEMPLATE.md).

## Задължително правило за източниците

**Всеки учебен модул съдържа секция `Оригинални източници` с директни линкове.**

Минимумът е:

1. оригиналното видео / статия / книга;
2. оригиналният примерен GitHub repository, ако има такъв;
3. официалната документация;
4. съответните JEP / RFC / specification документи;
5. допълнителните първични източници, използвани за актуализиране или проверка на материала.

Когато оригиналният материал използва по-стара или по-нова версия на Java, Spring или библиотека, нашият пример може да бъде адаптиран, но README трябва ясно да обяснява разликата и да запази линка към оригинала.
