# NotebookLM — Beyond Encryption at Rest: Computing on Encrypted Data

Използвай оригиналния [Devoxx запис на Andrea Iacono](https://www.youtube.com/watch?v=ePQyy9sLmsY) / предоставен SRT и *нашите конкретни локални източници*: [основния урок](README.md), [FHE schemes](FHE-SCHEMES.md), [trade-offs](FHE-TRADEOFFS.md), [OpenFHE execution lab](openfhe-lab/README.md), [Java oracle tests](src/test/java/bg/hristomanov/education/privacy/RiskScoreCalculatorTest.java).

Създай задълбочен **разговорен аудио урок на български** за Java 25 / Spring Boot backend разработчик. Започни с реален казус: HTTPS и Oracle 19c TDE защитават транспорт/диск, но външният compute worker трябва да обработва private данни без plaintext достъп. Обясни `data in use` и правилното trust boundary. Разкажи разликите между частично хомоморфен textbook RSA (НЕ production-safe), LWE, BFV с `t` и `q`, noise budget, leveled vs fully homomorphic encryption, bootstrapping, CKKS approximate reals и TFHE Boolean operations. Проследи **нашия изрично синтетичен** score `3*age + cholesterol -2*hdl +2*pressure +75*hypertension +120*smoker`, не го наричай истинска медицинска оценка. Покажи `baseline=430`, отрицателно `-400`, сравненията 499/500 и 999/1000, client-side classification, работа с `t=65537`. Обясни защо не можем да mock-ваме OpenFHE за correctness, защо има JUnit Java oracle върху общ CSV и **реален Python/OpenFHE C++ worker процес**. Раздели измерванията: context/keygen, encrypt, SerializeToFile, evaluation, roundtrip, decrypt, ciphertext bytes. **Не твърди, че демонстрационните 0.43 μs vs 7.71 ms важат за нашата среда.** Отдели криптографската privacy от integrity, metadata exposure, malicious client/worker, TLS/authZ и key management. Сравни FHE vs TEE vs MPC и default TLS/TDE. За всеки подход изрично: проблем, кога/кога не, печалби и загуби, по-проста алтернатива и конкретен изпълним тест. Завърши с 10 трудни въпроса за самопроверка без готови отговори.
