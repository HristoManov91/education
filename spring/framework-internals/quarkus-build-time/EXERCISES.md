# Упражнения — Quarkus Build-time и Jackson/JIT regression

> P2/P1, приблизително 3 сесии по 20–30 мин. Не маркирай темата като „усвоена“, докато не бъдат решени задачите и проверени тестовете. [Основен урок](README.md) и [JVM казус](../../../java/jvm/performance-evolution/QUARKUS-JACKSON-JIT-REGRESSION.md).

## Сесия A — BuildStep/BuildItem, Java 25

1. Защо не слагаме `GreetingBuildProcessor` в `runtime` модула? Какво влиза в Quarkus application runtime classpath?
2. Обясни как `CombinedIndexBuildItem` помага на `@BuildStep` да намери annotation без `Class.forName`.
3. Защо `GreetingModelBuildItem` наследява `SimpleBuildItem` и какво би станало при повече от един producer?
4. Кой конкретен `GeneratedBeanBuildItem`/Gizmo class се инжектира като `GreetingMessage`? Къде е source code — ръчно написан или генериран?
5. Изпълни `mvn -f spring/framework-internals/quarkus-build-time/pom.xml verify`. Какво доказва положителният Quarkus HTTP тест и какво не доказва за производителността?

## Сесия B — Negative tests и ownership

6. Добави в scratch branch втори `@GreetingDefinition` — кога трябва да се появи грешка? Защо не е приемлив runtime fallback „вземи първия“?
7. Промени съобщението да е празно и пусни тестовете на `GreetingRules`. Какви опасности носи generated bytecode от непроверени metadata?
8. Сравни това с Spring AOT: защо „Spring винаги прави runtime classpath scanning“ е неточно обобщение?

## Сесия C — JIT/performance

9. Изпълни `HandlerDispatchLabTest`. Защо са важни тестовете с непознат extension handler и с mutable входен списък?
10. Пусни локално JMH `HandlerDispatchBenchmark` за chainLength=1/3/9. Има ли доказано предимство на preclassification и защо резултат от benchmark за int операции не доказва HTTP throughput?
11. От оригиналните слайдове възстанови причините за първоначално по-бавния generated Jackson serializer: inlining, register spilling, profile pollution, loop unrolling.
12. Обясни разликата между JFR profile, JIT inline logs, generated assembly и Hyperfoil req/s. Коя информация от кое измерване може да е валиден извод?

## Senior checkpoint

Представи си: Spring Boot 4 / Oracle / Gateway, няколко JSON endpoint-а, след миграция Jackson 3 CPU се покачва, но p99 основно чака база данни. Колега предлага „Quarkus + reflection-free serializers“. Направи decision table: проблем, кога/кога не, печалби, загуби, по-проста алтернатива, API contract тестове, JFR/CPU evidence, rollout и rollback.

**Финал:** продължаваме със Spring, освен ако реалните изисквания и числата не мотивират друг избор.
