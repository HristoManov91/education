# P1 — Java upgrade diagnostics: `jdeprscan`, `jdeps`, binary compatibility

> [Ask the Architects (Devoxx 2026)](https://www.youtube.com/watch?v=ewCPBgOrLAE), ~09:30–17:50 от предоставения SRT. Архитектите описват консервативния процес за deprecation/removal, широкото изследване на реална употреба и миграционните последствия. Следващият **Java 25 лабораторен код е наш** — лекторите не демонстрират `jdeprscan` и `jdeps` в панела.

## 1. Реален казус

Spring Boot 3 → 4 или Java 21 → 25/27: кодът може да се компилира на старата JDK, но да извиква JDK API с предупреждение или вече премахната функционалност. Не решавай с изключване на всички warnings. Една dependency може да използва **отдавна deprecated** метод, без новият компилатор да вижда нейния source.

## 2. Изпълнима Java 25 лаборатория

| Демонстрация | Код | Проверка |
| --- | --- | --- |
| Deprecated JDK API, но все още компилируем на Java 25 | [LegacyBoxing](src/edu/upgrade/LegacyBoxing.java): `new Integer(42)` | `javac -Xlint:deprecation,removal` дава warning |
| Replacement contract | [ModernBoxing](src/edu/upgrade/ModernBoxing.java): `Integer.valueOf(42)` | без compiler warnings, идентичен business output |
| **Бинарна** проверка на deprecated JDK API | [run-lab.sh](run-lab.sh) | `jdeprscan` открива `java/lang/Integer` само в legacy artifacts |
| Анализ на директни JDK зависимости | [run-lab.sh](run-lab.sh) | `jdeps --list-deps` включва `java.base` |

```bash
bash java/jvm/jdk-upgrade-tooling/run-lab.sh
```

Този скрипт не е Maven module: компилира **две отделни** `target` директории с `javac`, очаква legacy warning, сканира байткод и проверява, че модерният код няма същия проблем. Работи без интернет и зависимости. Не публикуваме legacy demo като production library.

## 3. Как да тълкуваме резултатите

- `@Deprecated` е предупреждение. `@Deprecated(forRemoval=true)` е по-силен сигнал за бъдещо премахване, но не дава обещание **кога** API ще бъде махнато.
- `jdeprscan` е за **JDK** deprecated APIs в компилирани класове; **не** сканира произволни трети библиотеки за техни annotations. `--for-removal` филтрира само текущо маркираните за премахване. Не приемай, че `Integer(int)` е `forRemoval` само защото е deprecated — статусът може да се изменя.
- `jdeps` анализира статично известните class/package dependencies, включително `--jdk-internals`. **Не гарантира** откриване на имена, заредени динамично чрез reflection, ServiceLoader или runtime-generated bytecode.
- От Java 26 `Thread.stop()` е премахнат; стари binaries, които го използват, могат да хвърлят `NoSuchMethodError`. Това е *отделен официално документиран пример*, **не се изпълнява `Thread.stop` в лабораторията**.
- `--add-exports`/`--add-opens` могат временно да помогнат при module migration, но не заменят публичен поддържан API. Виж [JPMS executable lesson](../jpms-encapsulation/README.md).

## 4. Production migration checklist

1. Избери точните source, runtime, vendor и dependencies; вземи работещ baseline с тестове на старата версия.
2. Пусни **стария compiled artifact** на нов JDK, преди масови refactor-и; следи startup/runtime failures и deprecated JVM flags.
3. Пусни `jdeps --jdk-internals`, `jdeps --list-deps` и `jdeprscan --for-removal` с **пълен dependency classpath**.
4. Рекомпилирай с `-Xlint:deprecation,removal` и `--release` target; за зависимости/плъгини провери реална JDK compatibility матрица.
5. Замени deprecated functionality по бизнес договор; positive/negative tests и JDK 25/27 separate-process comparison.
6. За OpenJDK preview API потвърди действителния release статус; preview може да бъде **изтеглен** без finalization. Виж [Java Evolution Guide](../../JAVA-EVOLUTION-GUIDE.md).
7. Съхрани rollback, CI evidence, GC/CPU/RSS, и не прави неверни твърдения за binary/source compatibility.

**Кога:** JDK/Framework upgrade, подозрителни native/internal API-та или стар legacy JAR. **Кога НЕ:** вместо реален бизнес тест или за generic „performance optimization“. **Полза:** ранен сигнал за migration risk. **Цена:** непълни статични анализи, нужни са runtime/third-party tests. **По-проста алтернатива:** compiler warnings + scoped update на dependency, ако няма binary-only risks.
