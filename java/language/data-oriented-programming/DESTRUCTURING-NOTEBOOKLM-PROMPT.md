# NotebookLM · Destructuring, serialization и integrity (Richard Groß / Amber)

Използвай **предоставения SRT на Richard Groß** и [видеото Devoxx](https://www.youtube.com/watch?v=wcghmWdu-HY) като първичен източник. От Education добави [Java25 Deserialization & Encapsulation](DESERIALIZATION-AND-ENCAPSULATION.md), [Java26 JEP500 lab](../../jvm/final-field-integrity/README.md), [Data Interfaces/Deconstruction](DATA-INTERFACES-AND-DECONSTRUCTION.md), [Record Reconstruction](RECORD-RECONSTRUCTION-INVARIANTS.md) и [Amber Tech Radar](AMBER-FUTURE-DESIGN.md).

Направи задълбочена **разговорна лекция на български за Java/Spring backend developer**. Започни с production казус: `new Adult(17)` се отхвърля, но `ObjectInputStream` може да възстанови `LegacyAdult.age=17` без изпълнение на constructor. Обясни **точно** разликата между legacy Serializable, record canonical constructor при native deserialization, legacy `readObject` guard и ObjectInputFilter; покани слушателя да отвори 6 JUnit scenarios и да предвиди FAIL/PASS. Не казвай, че `ObjectInputFilter` прави untrusted native streams безопасни. Обясни защо Jackson/ORM не следват автоматично тази JDK native semantics.

След това сравни `private`/`final`/`deep reflection`/JPMS `opens`; Java25 reflection may mutate ordinary final field, **JDK26 default warn, debug, deny и scoped enable**. Разграничи record final-field protections от JEP500 общата история. Покажи stable class `PublicTimestamp(String)` със скрито `long epochMillis` и защо прозрачен record не винаги е подходящ API. Разкажи концептуално за **user-defined deconstruction, primary constructors, class patterns, reconstruction и withers**, но маркирай всеки незавършен syntax като **Amber proposal**, не Java25/26 production feature. Поправи несигурното изказване от Q&A: официалният Lombok `@With` създава нов обект чрез all-fields constructor, а не „може би мутира стария“; invariant въпросът остава.

За всеки подход имай: конкретен проблем, кога използваме, кога НЕ, ползи/загуби, по-проста алтернатива, директен пример и тест. Завърши с 10 практически въпроса за проверка без готови отговори. Не обещавай автоматично премахване на Java Serialization в конкретна версия.
