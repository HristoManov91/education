# NotebookLM — CRA + Threat Modeling + SBOM + Software Gardening

Използвай [основния CRA материал](README.md), [STRIDE Spring Security lab](../../../spring/security/threat-modeling/README.md), [SBOM accuracy](../../../spring/testing/testcontainers/SBOM-ACCURACY.md), [Software Gardening](../../../java/build/reproducible-maven/SOFTWARE-GARDENING.md) и оригиналния [Devoxx запис](https://www.youtube.com/watch?v=QQcsZNf0eWs) / предоставен SRT.

Направи задълбочен **разговорен аудио урок на български**, за Java 25 / Spring Boot backend разработчик. Започни с инцидент: production release има транзитивна CVE; по текущия `main` никой не знае кой image е засегнат. Води слушателя през product applicability и CRA legal review, four questions/STRIDE, Maven dependency tree, CycloneDX vs image SBOM и реconciliation, CVE triage, Dependabot/Renovate patch PR, tests, release evidence и reporting decision. За всяка техника: проблем, кога/кога не, ползи, trade-offs, по-прост вариант и директен runnable file/test. Отличи активно експлоатирана CVE от тежък инцидент; не интерпретирай всяка CVE като reportable. Разграничи 14 дни **след налична мярка** от 1 месец **след 72h уведомлението**. Не извеждай юридически заключения от техническа схема; укажи нормативен източник и date-sensitive nature. Разкажи защо по-малък брой компоненти в SBOM не доказва по-добро качество. Завърши с десет practically useful recall въпроса, без готови отговори.
