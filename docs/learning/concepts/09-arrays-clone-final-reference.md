# JAVA-FND-01 · Разширение — Java масиви, aliasing, `clone()` и `final` референции

**Ключови понятия:** array object, reference value, aliasing, reassignment, mutation, array cloning, shallow copy, object identity, final variable.

## Защо тази концепция е важна

Масивът е обект, а променлива от тип масив съхранява референция. Ако две променливи реферират един масив, промяната на елемент през която и да е от тях се вижда през другата. Това е основа за коректни API договори, defensive copying и избягване на неволно споделено mutable състояние.

## Mental model за 30 секунди

- `int[] alias = original` копира **стойността на референцията**; няма нов масив. Двете променливи реферират **един и същ обект**.
- `int[] snapshot = original.clone()` създава **нов масив** със същата дължина и копира елементите от първия. При `int[]` самите `int` стойности се копират.
- `alias[index] = value` е **mutation на елемент от реферирания масив**; `alias = snapshot` е **reassignment на променливата**.
- `alias == snapshot` проверява дали двете референции сочат **един и същ масив**, а не дали стойностите на елементите съвпадат.
- `final int[] original` забранява **повторното присвояване на променливата** `original` след инициализация, но не и промяната на елементи от нейния масив.
- Java референция не трябва да се описва като непременно **физически адрес в паметта**. Java Language Specification задава поведението, не конкретното представяне на референциите в JVM.

## Изпълним пример — диагностика, 2026-10-12

```java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        final int[] original = {1, 2, 3};

        int[] alias = original;
        int[] snapshot = original.clone();

        alias[0] = 10;
        snapshot[1] = 20;

        alias = snapshot;
        alias[2] = 30;

        System.out.println(Arrays.toString(original));
        System.out.println(Arrays.toString(alias));
        System.out.println(Arrays.toString(snapshot));

        System.out.println(alias == snapshot);
        System.out.println(original == snapshot);
    }
}
```

**Точен изход:**

```text
[10, 2, 3]
[1, 20, 30]
[1, 20, 30]
true
false
```

### Механизмът — стъпка по стъпка

1. `original` сочи към първия масив `[1, 2, 3]`, условно **A**. `final` фиксира референцията в променливата `original` след нейната инициализация, а не замразява A.
2. `alias = original` копира стойността на референцията към **A**: вече `original` и `alias` реферират A.
3. `snapshot = original.clone()` създава отделен масив **B**, с първоначално същите примитивни стойности `[1, 2, 3]`.
4. `alias[0] = 10` изменя елемент 0 на A. `original` вижда `[10, 2, 3]`. B остава независим.
5. `snapshot[1] = 20` изменя само B до `[1, 20, 3]`.
6. `alias = snapshot` пренасочва `alias` към B; `original` остава към A. Това присвояване не променя никакъв масив.
7. `alias[2] = 30` изменя B до `[1, 20, 30]`; стойността се вижда и през `snapshot`.
8. `alias == snapshot` е `true` (същият B); `original == snapshot` е `false` (A и B са различни обекти).

Ако след инициализацията опитаме `original = snapshot;`, получаваме **compile-time error**, защото `original` е `final` променлива. Не е правилно да говорим за „`final` обект“: модификаторът в този пример е върху **променливата**, не прави масива immutable.

## Защо `clone()` на обектни масиви изисква внимание

Клонирането на масив е **shallow copy**: създава нов външен масив и копира **стойностите на елементите**. При примитивни елементи се копират числа и други примитивни стойности. При референтни елементи се копират **референции**, не вложените обекти.

```java
StringBuilder[] first = {new StringBuilder("Java")};
StringBuilder[] second = first.clone();

System.out.println(first == second);       // false: два различни масива
System.out.println(first[0] == second[0]); // true: споделен StringBuilder

second[0].append(" 25");
System.out.println(first[0]);              // Java 25

second[0] = new StringBuilder("Other");
System.out.println(first[0]);              // Java 25: първият масив не е пренасочен
```

Промяната чрез `append()` изменя споделения обект. Присвояването на нов елемент в `second[0]` променя само слота от втория масив. Ако е нужен **deep copy**, трябва изрично да копираме и вложените mutable обекти според техния API/домейн.

## Професионален отговор

> Масивите в Java са обекти. При присвояване на масивна променлива се копира стойността на референцията, така че двете променливи могат да реферират един и същ масив. При извикване на `clone()` се създава друг масив и елементите се копират повърхностно. Затова промяната на елемент през alias се вижда през останалите референции към същия масив; reassignment само променя кой масив реферира конкретната променлива. `final` забранява пренасочване на референтната променлива след инициализация, но не забранява mutation на обекта. При масиви от обекти `clone()` не копира самите обекти, а референциите към тях.

## Текст за слушане

В Java масивът е самостоятелен обект. Когато присвоим една масивна променлива на друга, не създаваме втори масив. Копира се стойността на референцията. Така две имена могат да обозначават един и същ масив и промяната на елемент през едното се вижда и през другото. Това явление се нарича aliasing.

При извикване на clone върху масив се създава нов масив. Ако е от цели числа, елементите са примитивни стойности и се копират по стойност. Новият масив може да бъде променян независимо. Ако после пренасочим първата локална променлива към новия масив, променяме само нейната референция, а не съдържанието на стария масив.

Final върху променлива от тип масив означава, че след първоначалното ѝ присвояване не можем да я пренасочим към нов масив. Final не прави елементите непроменяеми. Това разграничение между самата референция и състоянието на обекта е основополагащо.

И още една важна подробност: клонирането на масив от обекти е повърхностно. Двата масива са различни, но елементите им първоначално могат да реферират едни и същи обекти. Затова мутация на вложен обект може да се наблюдава през двата масива, докато подмяна на референция в един от масивите засяга само него.
