# JAVA-FND-02 — Предаване на аргументи в Java: pass-by-value, mutation и reassignment

**Ключови термини:** argument, parameter, pass-by-value, reference value, object mutation, local reassignment.

## Защо това е важно

В API метод често получава DTO, entity или друг mutable обект. Трябва да знаем дали методът може да промени **състоянието на подадения обект**, и дали може да смени **референцията в променливата на извикващия код**. Това са две различни действия.

## Най-важното за 30 секунди

**Java винаги предава аргументите по стойност (pass-by-value).**

- При `int` се копира числовата стойност.
- При `Person` се копира стойността на референцията към `Person` обекта — **не** обектът и **не** самата променлива от извикващия метод.
- Ако параметърът сочи към изменяем обект, методът може да го **изменя**.
- Присвояването на друга референция на параметъра променя **само локалния параметър**, не променливата на извикващия код.

## Изпълним пример — Въпрос 2

```java
public class Main {

    static class Person {
        String name;

        Person(String name) {
            this.name = name;
        }
    }

    static void change(Person person, int age) {
        person.name = "Maria";
        person = new Person("Peter");
        age = 30;
    }

    public static void main(String[] args) {
        Person p = new Person("Ivan");
        int age = 20;

        change(p, age);

        System.out.println(p.name);
        System.out.println(age);
    }
}
```

**Изход:**

```text
Maria
20
```

### Проследяване по стъпки

1. В `main` `p` съдържа референция към обект `Person` с `name = "Ivan"`, а `age` съдържа `20`.
2. При `change(p, age)` Java копира стойността на референцията от `p` в **новата локална параметърна променлива** `person`. Копира и числото `20` в локалния параметър `age`.
3. Първоначално `p` и `person` сочат към **един и същ обект**. `person.name = "Maria"` променя полето в този обект. През `p` вече се вижда `Maria`.
4. `person = new Person("Peter")` създава втори обект и променя **само локалната** референция `person`. `p` продължава да сочи към първия обект с `Maria`.
5. `age = 30` променя само локалната променлива `age` в метода. Променливата `age` в `main` остава `20`.
6. След връщане от метода локалните му параметри не са достъпни. В този пример `p.name` остава `Maria`, `age` остава `20`.


## Професионален отговор (за колега или интервю)

> Java използва pass-by-value за всички аргументи. При примитивен тип се копира примитивната стойност, а при референтен тип — стойността на референцията към обекта. Затова параметърът `person` и променливата `p` са независими променливи, но в началото сочат към един и същ `Person`. Изменението на полето `name` засяга споделения обект. Присвояването на нов `Person` на `person` променя само локалната референция и не пренасочва `p`. Аналогично промяната на локалния примитивен параметър `age` не изменя `age` в извикващия метод.

## Текст за слушане

Когато извикваме метод в Java, стойностите на аргументите се копират в параметърните променливи на метода. Това е смисълът на понятието pass-by-value. Механизмът е един и същ за примитивните и референтните типове, но копираната стойност е различна.

Ако изпратим цяло число двадесет, локалният параметър получава копие на числото. Промяната му на тридесет не засяга променливата в извикващия метод. Ако изпратим променлива, която сочи към обект Person, локалният параметър получава копие на стойността на референцията. Затова двете различни променливи първоначално сочат към един и същ обект.

Оттук следват две различни поведения. Когато през локалния параметър променим полето name на съществуващия обект, промяната се вижда и в извикващия код. Когато обаче присвоим на локалния параметър нов обект Person, сменяме само референцията, съхранена в тази локална променлива. Променливата на извикващия продължава да сочи към първоначалния обект.

Затова не е точно да казваме, че Java предава обектите по референция. По-точно е да кажем, че Java предава по стойност референцията към обекта. Това разграничение е решаващо при работа с DTO, entities и изменяеми колекции.

## Провери се без подсказване

1. Ако в `change` не променим поле, а изпълним само `person = new Person("Peter")`, може ли `p` от `main` да започне да сочи към новия обект?
2. Защо метод може да промени поле на подаден обект, но не може чрез обикновено присвояване на параметъра да пренасочи променливата на извикващия код?
