### Защо коригирахме терминологията (без да отнемаме верния резултат)

**Знание, което потребителят показа:** `a` остава 10, `b` става 20, двете `StringBuilder` референции дават `AB` след `append()`.

**Конкретен пропуск:** неточно противопоставяне „примитивите имат стойности, обектите са в паметта“.

**Пример за професионално обяснение (за четене след самостоятелния recall, не преди него):**

> При присвояване на примитивна променлива се копира стойността ѝ, затова промяната на `b` не променя `a`. При присвояване на референтна променлива се копира референцията: `sb1` и `sb2` реферират един и същ изменяем обект `StringBuilder`. Когато извикаме `append()` през `sb2`, променяме състоянието на този обект, което се наблюдава и през `sb1`.

**Забележка:** обяснението не е „примитивите са извън паметта“ или „всички примитиви са stack, всички обекти са heap“. Няма нужда от JVM implementation assumptions, за да се обясни Java семантиката.

### Следващият незавършен въпрос (не показвай решение предварително)

От предишния разговор; **все още чака отговор**. Насочва към `JAVA-FND-02`, но не финализира `JAVA-FND-01` самостоятелно:

```java
public class Main {

    static class Person {
        String name;

        Person(String name) {
            this.name = name;
        }
    }

    static void change(Person person, int age) {
        person.name = "Maria";
        person = new Person("Peter");
        age = 30;
    }

    public static void main(String[] args) {
        Person p = new Person("Ivan");
        int age = 20;

        change(p, age);

        System.out.println(p.name);
        System.out.println(age);
    }
}
```

**Питай:** „Какво ще отпечата програмата и защо? Каква е разликата между `person.name = "Maria"` и `person = new Person("Peter")`?“ Не подсказвай отговор, преди човекът да опита. Ако има изискуем D+1/D+7 recall, първо го направи за 2–5 минути, след което продължи тук.
